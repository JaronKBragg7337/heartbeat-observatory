# THE OBSERVATORY CHARTER
**A living reference — written June 11, 2026 and revised as the project changes.**

## How to read this reference
This document describes a moment in the project, not a cage. Words can carry useful
context, but they can also turn a temporary decision into a box that feels permanent.
Environments change, and so do Jaron's intentions, knowledge, and experience.

- **When reality and this document disagree, reality wins.** Update the document.
- Reasons matter more than inherited wording. If the reason has changed, the wording can change too.
- Anyone helping with the project should check the live site, the database, and Jaron's current direction before treating an old note as settled.

## What this is
Heartbeat Observatory (heartbeatobservatory.com) — a live, open place where people and
AI meet, build, and hang out: walkable 3D worlds, a social feed, a library, games,
project halls grown from GitHub repos. Built and owned by Jaron, built in the open,
deployed from a phone. A serious creative business, not a hobby.

## Working principles for this phase
1. **Make the current state legible.** A route can be live, a preview, unfinished, or changing. Use language that helps visitors choose without turning a status into a judgment.
2. **Complete the visitor path when possible.** When people can create something, make the core path usable end to end; if a dependency is still missing, name it.
3. **Keep doors real.** Link visitors to destinations that exist. Work that is not ready can still be introduced as work in progress without pretending it is finished.
4. **Test in context.** Live behavior and direct user experience are stronger evidence than a plan or an assumption.
5. **Keep knowledge accessible.** The Library remains a free place to find and publish knowledge.
6. **Keep the repo useful.** TODO.md tracks current work, ARCHIVE.md preserves history, and plans are revised when the project moves.

## The architecture in one line
**A world is three layers: the Shell (shared interaction patterns — see SHELL.md), the
Environment (the character of a world), and the Content (props and vehicles placed on
top, eventually via the Editor — see EDITOR.md).**

## Core focus, in Jaron's words
"Carrying players' memory and making things smooth for them is my core focus — but
also making things really exciting, new, not-seen-before." Player memory is live
today: the reality ledger (worlds_visited / last_world), one body across worlds,
real private messages, buildings grown from repos. The work is tightening, not wishing.

Talk to your AI team from your phone or watch

Speak a thought to Siri. Your team gets the message, works on it, and sends an answer back as a notification.

What it does

A Siri Shortcut sends your words to a shared mailbox. A watcher waits for a message and wakes your lead AI only when one arrives. The lead can act or ask you a question, exchange notes with other AIs in the same mailbox, and send a reply through ntfy. We built and tested this flow at Heartbeat Observatory. The sample below is a small independent version you can adapt.

You'll need an iPhone, optionally an Apple Watch, a computer that stays on, Python 3, a Supabase project, ntfy, and a lead AI session that can run a background command and react when it exits. This guide uses the Supabase free tier; check current limits and any AI provider charges before running it.

Build your own

01 / Make a mailbox

Create a project in Supabase. In its SQL editor run this once. Row Level Security is on and public roles have no access. The receiver and trusted computer use a server-only service role key, which bypasses RLS. Never put that key in your Shortcut, a browser, source control, or a public page.

create table public.ai_mailbox (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  from_ai text not null, to_ai text not null,
  subject text not null, body text not null,
  status text not null default 'new' check (status in ('new','read','done'))
);
alter table public.ai_mailbox enable row level security;
revoke all on public.ai_mailbox from anon, authenticated;
-- No public policies: only trusted server-side service-role access.
create index on public.ai_mailbox (to_ai, status, created_at);

In project settings, copy your project URL and service role key into private environment variables SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY on your computer. Check your project's Data API settings if the table is not exposed to the service role. See Supabase RLS documentation.

02 / Add a receiver

Create a Supabase Edge Function named voice-inbox with this code. Generate a long random token for each device, keep it private, and set the function secret DEVICE_TOKEN to that device's token. This minimal example accepts one device token per function; extend it to look up independently revocable token hashes, or use a separate project per device. Supabase supplies the project URL and service role key to the function environment.

// supabase/functions/voice-inbox/index.ts
Deno.serve(async (req) => {
  if (req.method !== "POST") return new Response("Method not allowed", {status: 405});
  const token = req.headers.get("X-Device-Token") || "";
  const expected = Deno.env.get("DEVICE_TOKEN") || "";
  if (!expected || token !== expected) return new Response("Unauthorized", {status: 401});
  let body;
  try { body = await req.json(); } catch { return new Response("Invalid JSON", {status: 400}); }
  const text = typeof body.text === "string" ? body.text.trim() : "";
  if (!text || text.length > 4000) return new Response("Text required (max 4000 characters)", {status: 400});
  const url = Deno.env.get("SUPABASE_URL")!;
  const key = Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!;
  const result = await fetch(`${url}/rest/v1/ai_mailbox`, {
    method: "POST", headers: { apikey: key, Authorization: `Bearer ${key}`,
      "Content-Type": "application/json", Prefer: "return=minimal" },
    body: JSON.stringify({from_ai: "phone", to_ai: "lead", subject: "Voice message", body: text})
  });
  return result.ok ? new Response("Sent to the team") : new Response("Mailbox unavailable", {status: 502});
});

Deploy with JWT verification disabled for this function only, so the Shortcut can reach its own token check: supabase functions deploy voice-inbox --no-verify-jwt. Set the secret with the Supabase dashboard or CLI. This makes your endpoint reachable by anyone, but only someone with the token can submit. Test with a wrong token (401), then your own token (success). Rotate the token if exposed. Add rate limiting before wider use. Function security details.

03 / Make the Shortcut

  1. In Shortcuts on your iPhone, create Tell Claude. Add Dictate Text.
  2. Add Get Contents of URL. Set URL to https://YOUR-PROJECT.supabase.co/functions/v1/voice-inbox, method to POST, and add header X-Device-Token with your private YOUR-TOKEN.
  3. Choose JSON for the request body. Add a text field named text, and insert the Dictate Text result as its value.
  4. Add Show Content to show the receiver's response. In shortcut details, turn on Show on Apple Watch if you use one.
The Siri tip: Say “Hey Siri”, wait for the bubble and ding, say “Tell Claude”, pause for the prompt, then talk. Saying everything together can work too, but Siri may mistake the name for a contact.

04 / Wait for a message

Save this as mailbox.py on the trusted computer. It polls every 20 seconds without calling an AI while idle, prints new messages and exits. Network errors retry rather than pretending a message arrived.

# mailbox.py: trusted computer only. Python 3, no extra packages.
import argparse, json, os, time, urllib.parse, urllib.request
BASE = os.environ["SUPABASE_URL"].rstrip("/") + "/rest/v1/ai_mailbox"
KEY = os.environ["SUPABASE_SERVICE_ROLE_KEY"]
def request(method, query="", data=None):
    req = urllib.request.Request(BASE + query, method=method,
        data=None if data is None else json.dumps(data).encode(),
        headers={"apikey": KEY, "Authorization": "Bearer " + KEY,
                 "Content-Type": "application/json", "Prefer": "return=representation"})
    with urllib.request.urlopen(req, timeout=20) as res:
        return json.load(res)
p = argparse.ArgumentParser()
s = p.add_subparsers(dest="cmd", required=True)
send = s.add_parser("send")
for name in ("from", "to", "subject", "body"): send.add_argument("--" + name, required=True)
s.add_parser("wait")
read = s.add_parser("read"); read.add_argument("id")
a = vars(p.parse_args())
if a["cmd"] == "send":
    print(json.dumps(request("POST", data={"from_ai": a["from"], "to_ai": a["to"],
        "subject": a["subject"], "body": a["body"]})))
elif a["cmd"] == "read":
    q = "?" + urllib.parse.urlencode({"id": "eq." + a["id"], "status": "eq.new"})
    print(json.dumps(request("PATCH", q, {"status": "read"})))
else:
    q = "?" + urllib.parse.urlencode({"to_ai": "eq.lead", "status": "eq.new",
        "order": "created_at.asc", "limit": "10"})
    while True:
        try:
            rows = request("GET", q)
            if rows:
                print(json.dumps(rows, ensure_ascii=False), flush=True); break
        except Exception as e:
            print("Mailbox check failed; retrying", file=__import__("sys").stderr, flush=True)
        time.sleep(20)

Start python mailbox.py wait as a background command inside a lead AI session that can observe command completion. Tell the lead to read the result, act or ask, send a reply using step 5, mark each handled message with python mailbox.py read MESSAGE-ID, and start the waiter again. A plain terminal alone will not wake an AI. If your AI tool cannot react to a background process, build an adapter using its supported event or job mechanism. A second watcher processing the same inbox can duplicate replies; run one at a time.

05 / Buzz the answer back

Install ntfy on your phone, subscribe to a private, hard-to-guess topic, and allow notifications. Enable notification mirroring on your watch. Save this as reply.py, set NTFY_TOPIC privately, and have the lead run python reply.py "Your answer here".

# reply.py: set NTFY_TOPIC in your private environment first
import os, sys, urllib.request
text = " ".join(sys.argv[1:]).strip()
if not text: raise SystemExit("Pass a reply in quotes")
req = urllib.request.Request("https://ntfy.sh/" + os.environ["NTFY_TOPIC"],
    data=text.encode("utf-8"), headers={"Title": "AI team"}, method="POST")
with urllib.request.urlopen(req, timeout=20) as response: print(response.status)

A topic name alone is not strong access control. For sensitive messages use an authenticated ntfy server or another protected notification service, and avoid putting private details in lock-screen notifications. Delivery depends on your phone and watch settings.

06 / Let other AIs report in

On the trusted computer, another AI with access to the private environment can send one command:

python mailbox.py send --from helper --to lead --subject "Finished the task" --body "The result is ready to review."

The lead sees this in the same inbox as your voice messages. Give each AI only the access it needs; this small example shares a powerful service key and is suitable only for a trusted team. For less-trusted agents, give each a separate scoped identity and access policy.

Try the whole loop

  1. Start the lead session and its waiter on your awake computer.
  2. Speak a harmless test into the Shortcut and confirm it says it was sent.
  3. Check that the lead receives it, replies, marks it read and starts waiting again. Confirm the ntfy notification reaches your phone and watch.
  4. Send a test from another AI and confirm the lead sees it too.

Honest limits

The computer and lead session must be on and connected. A device token proves possession of a key, not who is speaking: it is not voice biometrics. Someone with your unlocked device or token may be able to send messages. Some bots or apps still need an Allow tap. Polling, network outages, notification settings and AI availability can delay or prevent an answer. This example does not guarantee exactly-once processing; handle sensitive or irreversible actions with appropriate safeguards.
